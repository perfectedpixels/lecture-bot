Create a persona for your AI Agent experience. Base the AI Agent Persona on the following criteria by describing your AI Agent with the key points covered in our lecture:

  1. Name of your Agent

  2. Purpose & Value Proposition

    • What specific value does the agent provide to the user and product?

  3. Role Archetype

    • The agent’s personality, tone, and communication style

    • (e.g., supportive guide, expert assistant, operational co-pilot)

  4. Initiative Level

    • How proactive the agent is

    • When it suggests, acts, or waits for user input

  5. Capabilities

    • Exact tasks the agent can perform

    • Data sources or inputs it can access

  6. Interaction Context

    • Modes of interaction (text, voice, visual, system-triggered, etc.)

  7. Memory Behavior

    • What the agent remembers

    • How personalization is balanced with privacy and security

  8. Tools Used

    • Systems, services, or components the agent integrates with

  9. Explainability & Transparency

    • How users understand why the agent made a decision or suggestion

  10. Boundaries & Constraints

    • Clear limits on agent authority and behavior

    • Safeguards against misuse or overreach

  11. Risks & Open Questions

    • Potential failure modes, ethical risks, or unintended consequences

  12. Success Metrics

    • How you will measure whether the agent is effective

    • (e.g., task completion, error reduction, trust signals)

 

Sample Assignment 

 

AI Design Principles

Purpose:
This document defines the non-negotiable principles students must follow when designing AI agents in this course. These principles are not philosophical—they are design constraints.

1. Agent behavior is a design artifact

The behavior of an AI agent is as much a UX artifact as a persona, journey map, or information architecture.

  • Agents must have defined roles, boundaries, tone, and escalation logic.
  • “Prompting” is not interaction design;behavioral specification is.
  • An agent that behaves inconsistently or opaquely is a design failure.

2. Assistance, not ownership

AI agents may support human decision-making, but must not replace it.

  • The agent should guide, frame, summarize, and surface options.
  • The agent must not decidefor the user in high-impact contexts.
  • Human-in-the-loop is a success criterion, not a feature request.

3. Context determines risk

The same AI capability can be benign or harmful depending on where it appears in the user journey.

  • Low-consequence contexts tolerate exploration and error.
  • High-consequence contexts (health, mental well-being, safety, identity) require strict constraints.
  • Agents must adapt behavior based on journey moment, not just user intent.

4. Constraint is a feature, not a limitation

Unconstrained agents are irresponsible agents.

  • Agents must explicitly refuse, redirect, or escalate when outside scope.
  • “The model decided on its own” is not an acceptable explanation.
  • Safety, privacy, and ethical boundaries must be designed, not assumed.

5. Failure is a design signal

Initial AI outputs will be wrong. This is expected.

  • Designers are responsible for shaping outcomes through iteration.
  • Testing, failure analysis, and refinement are core deliverables.
  • A system that cannot fail safely is not ready to exist.

6. The user must remain connected to the human experience

AI should reduce friction, not agency.

  • Agents should reinforce user understanding, confidence, and control.
  • Emotional dependency, over-trust, or false authority are design risks.
  • UX quality includes what the agentdoes not 

What we are listening for:

  • Does the agent’s behavior clearly derive from the user persona and journey?
  • Are different journey moments treated with different levels of caution and control?
  • Is the agent’s value proposition aligned with user goals, not technical capability?

Red flags:

  • Generic assistant behavior
  • Persona reduced to tone only
  • No distinction between low- and high-risk moments

 

 

What a Bad AI Agent Looks Like

(And Why It’s a UX Failure)

🚫 Signs of a Poorly Designed AI Agent

  1. Takes ownership instead of assisting
  • Makes decisions for the user rather than guiding them
  • Optimizes for “getting to an answer” instead of supporting understanding
  • Removes human judgment from high-impact moments
  1. Has no clear boundaries
  • Attempts to answer everything
  • Lacks refusal or escalation behavior
  • “Solves” problems it should never touch
  1. Ignores context and risk
  • Behaves the same in low- and high-consequence situations
  • Treats all user requests as equal
  • Fails to recognize vulnerable or sensitive states
  1. Is unconstrained by persona or journey
  • Sounds generic regardless of user, brand, or moment
  • Tone is cosmetic, not behavioral
  • Cannot explain why it responds the way it does
  1. Cannot fail safely
  • Overconfident responses
  • Hallucinates certainty
  • No recovery path when information is missing or conflicting

⚠️ Why This Matters

A bad AI agent:

  • Breaks trust
  • Encourages over-reliance
  • Disconnects users from the human experience
  • Creates real risk, not just bad UX

If the agent “decides on its own,” the design has failed.
